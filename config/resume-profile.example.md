# 简历画像（示例模板）

> 复制本文件为 `config/resume-profile.md` 后按自己的真实情况填写。
> `config/resume-profile.md` 已被 `.gitignore` 忽略，个人信息不会进入仓库。
> 本文件是岗位匹配打分的唯一依据，改了简历就同步改这里，不要靠记忆。

## 一、硬性条件

| 项 | 值 | 说明 |
|---|---|---|
| 现居 | 城市 / 是否接受异地 | 异地岗位按城市、搬迁成本单独评估 |
| 年龄 | 年龄（出生年份） | |
| 学历 | 学历 · 学校 · 专业 | 说明专业是否对口 |
| 工作年限 | N 年（起止时间） | |
| 英语 | 读写/听说水平 | 外企岗位可作加分项 |
| 驾照 | 有无 / 熟练程度 | 路试、整车试验类岗位加分 |
| ⚠️ 空窗期 | 起止时间与原因 | 面试必问，提前准备说法 |

## 二、经验主线（按含金量排序）

| 时间 | 公司 | 角色 | 核心内容 |
|---|---|---|---|
| YYYY.MM–YYYY.MM | 公司 A | 岗位 | 负责的系统 / 项目 / 产出与量化结果 |
| YYYY.MM–YYYY.MM | 公司 B | 岗位 | 负责的系统 / 项目 / 产出与量化结果 |
| YYYY.MM–YYYY.MM | 公司 C | 岗位 | 负责的系统 / 项目 / 产出与量化结果 |

**主线定位（一句话）**：把最能打动目标岗位的经历压缩成一句话。

## 三、技能清单

**测试工具**
列出熟练使用的工具链，例如 CANoe、CANape、ECU-TEST、JIRA、缺陷管理平台。

**自动化测试**
自动化环境搭建、脚本开发、报告生成等能力。

**车载协议与标准**
CAN / LIN / 以太网 / UDS / 相关国标等。

**系统与脚本**
Linux、ADB、Python、Shell 等。

**加分项**
与目标岗位相关、但不属于主线的能力。

## 四、求职意向

**目标岗位**：示例 —— 车载测试工程师 / 测试开发工程师 / 测试管理

**对口岗位类型**（title 含以下即视为职能匹配）
整车测试、HIL 测试、集成测试、IVI 测试、车机测试、智能座舱测试、OTA 测试、
车联网/T-Box 测试、诊断测试、ECU 测试、测试管理/测试组长等。

> **排除方向**：在这里写清楚不投的方向（例如 ADAS/智驾），并与
> `config/keywords.json` 的 `excludeRoles` 保持一致。

## 五、加分信号

- 岗位描述出现：工具名、协议名、自动化、测试平台、测试管理职责
- 目标行业的头部公司、外资 Tier1、检测认证机构
- 有量化交付结果、带团队、跨团队协作
- 薪资结构规范、职级匹配

## 六、减分信号

- 纯手工「点点点」测试，无自动化、无脚本
- 明确「长期出差」「外派」「驻场」
- 非目标行业的同名岗位
- 匿名岗位，无法判断公司性质
- 招聘方是猎头或人力外包

## 七、明确排除

- 不投的技术方向（例如 ADAS/智驾：感知、规控、泊车等）
- 销售 / 客服 / 讲师 / 人事等非技术岗位
- 应届生岗、学历硬门槛不符的岗位
- 非目标行业的测试岗

## 八、薪资参照

- 按岗位所在城市单独判断，不要用单一区间一刀切
- 写下可接受的最低线，以及需要警惕的异常区间

## 九、搜索词（驱动 `config/keywords.json`）

按「命中独占岗位数」筛选后的有效搜索词：

```
关键词1 / 关键词2 / 关键词3 / 关键词4 / 关键词5
```

> 说明：如果怀疑某类岗位漏抓，先把对应词临时加回 `config/keywords.json` 试一轮。
